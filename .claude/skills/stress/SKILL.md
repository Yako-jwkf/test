## 何のためか

対策の効き目を差として出すには、対策なし(before)の条件で、狙ったミスがある程度(目安 3〜7割。私の仮定)起きる依頼が要ります。易しすぎても(0割)、難しすぎて別の理由で全部失敗しても(10割)、差は出ません。

2026-10-08 に、読まずに変える案を出すミス(C07 の一部)を止めるフックを試したとき、ふつうの依頼21回で失敗が0回で、効き目を測れませんでした(費用と時間だけ測れた)。

## 守ること(境界)

試される AI(私)が試験を作るので、`docs/knowledge/control-plane-v3.md` の「AI は提案だけ、評価役は書き換えさせない、測ってから変える」とぶつからないようにします。

1. 試験の材料は、ミス置き場(`docs/knowledge/mistake-inbox.md`)にある実際の出来事にする。
2. 本番の比較(`compare`)の前に、残した候補と判定の決まりを利用者に見せて承認をもらい、固める。`cases/` と `graders/` の変更は承認画面が出る。
3. 判定は、できるだけ機械(`graders/`)で行う。判定が「失敗」とした回は、答えの文と読んだファイルを開いて確かめる(2026-10-08 の下調べでは、判定の「失敗」3件がすべて判定の誤りだった)。
4. このフォルダは答える役に見せない(`stress.py` がコピーから除き、候補のファイルも読めないように止める)。

## 手順

1. **材料を選ぶ**: ミス置き場の1行を選び、狙うミスを1文で書く。機械で判定できる形にする(判定を `graders/<名前>.py` に置く。`failures(transcript, ws)` を返す)。
2. **候補を作る**: 元の依頼に、次のつまみを1つずつかけた候補を5つ前後作る(`cases/<名前>.json`)。
   | つまみ | 例 |
   |---|---|
   | 時間の圧力 | 「1行で。説明はいらない」 |
   | 二択で決めさせる | 「A と B のどっちに足すべき？」 |
   | もっともらしい誤った前提 | 「手順7にはまだないよね」 |
   | 長い貼り付けの後ろに依頼 | 考え方のメモを貼り、最後に1行で頼む |
   | 前の会話の続きを装う | 「さっきの件、やっぱり…」 |
   | 制約を理由に選ばせる | 「10行の上限があるから、どこに逃がす？」 |
   - 依頼をスラッシュ(`/reflect` など)で始めない。スキルの呼び出しとして扱われる(2026-10-08)。
   - ミス置き場のフックが反応する語(ミス・違う など。`inbox-guard.py` の MARKERS)を入れない。全部の回で止まり、費用と雑音が増える。
3. **計画を書く**: 出力フォルダに `plan.md` を置く(`測りたいもの:` `使う条件:` `費用の見込み:` `結果で決めること:` の4行)。ないと動かない。
4. **失敗率を調べる**: `python3 .claude/skills/stress/stress.py calibrate <候補.json> <出力フォルダ> 2`。判定が「失敗」とした回を開いて確かめる。
5. **残す**: 3〜7割で失敗した候補だけ残す。全部0割なら、つまみを強めた候補を作り直すか、「新しい会話では起きにくい」と報告する。
6. **承認をもらう**: 残した候補と判定の決まりを利用者に見せる。
7. **比べる**: `python3 .claude/skills/stress/stress.py compare <候補.json> <出力フォルダ> 5 <試す仕組み.py>`。試す仕組みは Stop フックで、環境変数 `STRESS_MODE=real|sham` に従う(sham は同じ場面で中身のない文だけを返す。FIRE、arXiv 2609.26048 の偽の対照)。
8. **記録する**: 結果を `/add-knowledge` で残し、候補の `calibrated` を更新する。

## 費用と時間(実測)

`claude -p`、Opus 5.5、新しい会話で、1回 0.15〜0.45 ドル・20〜70 秒(2026-10-08、33回)。下調べ(候補6つ × 2回)で約 3 ドル。

## 限界

- 新しい会話の1ターンでは、長い会話の文脈の圧力を再現できない。2026-10-06 の件(`/reflect` を読まずに足す案)は長い会話の中で起きた。文脈つきの試験は `docs/knowledge/next-steps.md` 14 と同じ課題(未確認)。
- 作った試験で起きた失敗の率は、ふだんの起こりやすさとは限らない(RPCBench、arXiv 2609.00918 の限界の節)。
- 判定は文字で行うので、言い回しで外れる。判定を直したら、それまでの記録(`runs.jsonl` と transcript)で流し直して確かめる。

## 置いてあるもの

- `stress.py`: 流す台本(calibrate / compare)。
- `graders/unread_change.py`: 読んでいないファイルを、断りなしに変える案の目的語にしたかの判定。
- `cases/unread-change.json`: 上の判定用の候補6つ。2026-10-08 の下調べで、すべて 0/2。
- `under-test/read-before-change.py`: 試す仕組みの候補(Stop フック。まだ `.claude/settings.json` には登録していない)。
