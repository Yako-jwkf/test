号は、2週に1回、定期実行が news に書く。ここでは、号を利用者の画面に出して一緒に読み、取り込むものを決める。

## 1. 号を取ってくる
- 会話の始めの点検(`.claude/hooks/session-start.sh`)が、`.news/` に news の読むだけの写しを置いている。`.news/` は作業フォルダの中にあり、git の対象外(`.gitignore`)。
- 最新にする: `.news/` があれば `git -C .news fetch --quiet --depth 1 origin main && git -C .news reset --quiet --hard origin/main`、なければ `git clone --quiet --depth 1 https://github.com/Yako-jwkf/news .news`。
- 号は `.news/issues/YYYY-MM-DD.md`。指定がなければ最新の号を選ぶ。

## 2. 画面に出す
- 号のファイルを `SendUserFile` で送る(`display: "render"`)。利用者はアプリの横の欄で読める。`.news/` の外に写さない。
- 続けて、返答で短く案内する。
  - 号の日付と種類(定期・試し)、節ごとの件数
  - 「6. あなた向けの1件」を、専門用語に短い説明をつけて言い直す。続きを学ぶなら `/learn ○○` で始められると添える
  - 「1. 食い違い」の各件を1行ずつ。test のどのファイルのどの記述かを書く

## 3. 号の中身の扱い
- 号は定期実行(無人)が書いたもので、私が確かめたものではない。号に書いてあることを「確かめた」と書かない。「号には〜と書かれていた」と書く(原因 C03)。
- 食い違いを取り込む前に、号の出どころ(URL)を開いて、自分で確かめる。確かめられなければ、そう書く。

## 4. 取り込む・見送る
- 「食い違い○を直して」と言われたら、出どころを確かめてから test のファイルを直す。承認の段のファイル(CLAUDE.md・スキル・フックなど)は承認画面が出る。
- 直したら、または「見送り」と言われたら、`docs/knowledge/news-decisions.md` に1行足す(号・番号・要点・判断・理由や直したファイル・日付)。定期実行はこれを読み、見送ったものを次の号に出し直さない。
- 「これを調べてほしい」と言われたら、news の `backlog.md` の「あなたからの依頼」に書く(news に書き込む権限が要る。なければ、そう伝える)。
