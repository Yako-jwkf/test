# 改良案(2026-10-06、メンテナンスのあとで)

要約: ミスから学ぶ仕組みは「記録する・束ねる・対策を置く」まではできている。弱いのは「対策が本当に効いたかを、AI の甘い採点に頼らずに確かめること」と「効かない対策を減らすこと」。メンテナンスで見つけた事実と研究から、案を7つにまとめた。採用は未決定。私の推しは最後の節。

用語: フック=決まった時点で自動で動く小さなプログラム。judge=再テストで答えを採点する AI。LEAK_FILES=再テストのとき、答える役から隠すファイルの一覧。

## この案の目的
対策を「置いた」だけでなく「効いた」と言えるようにし、効かない対策を消せるようにする。あわせて、利用者が毎回判断しなくて済むようにする(原因 C23)。

## 案
各案に「何のためか・中身・根拠・代償・効かないこと」を書く。保護の段(deny=変更手順が要る、ask=承認画面)も書く。

### A. 判定を確かにする
**A1. 判定の名前を分ける**(ask: `scripts/mistake_check.py`)
- 何のためか: 「動く」と「効いた」を取り違えないため(F2)。
- 中身: 振る舞いと残存の確認だけで付いた合格を「仕組みは動く(効き目は未測定)」にし、再テストか本番の再発の数で確かめたものだけ「合格」と呼ぶ。会話の開始時の要約も、この2つを分けて出す。
- 根拠: F2。Memory Reward Inflation の報告(点数の水増しが、次の判断を誤らせる)。
- 代償: 台本の数行と試験の更新。数分。
- 効かないこと: 効き目そのものは測らない。見え方を正すだけ。

**A2. judge に「元の悪い答え」も毎回採点させる**(deny: `/retest`)
- 何のためか: 採点の条件がゆるいと、悪い答えも合格する。それを測る前に見つけるため(F7)。
- 中身: 事例ごとに「元の悪い答え」(と、あれば良い答え)を固定の見本にする。再テストのたびに judge に見本も採点させ、悪い見本が合格した条件は「条件を直す」として結果を使わない。
- 根拠: F7(2026-10-02 に実際に起きた)。Who Judges Matters(同じ系統のモデルを甘く見る)。Memory Reward Inflation(別のモデルや多数決では偏りが消えなかった。採点役の外の証拠で点を直す方が効いた)。見本は合否が人の指摘で決まっているので、採点役の外の物差しになる。
- 代償: 採点が条件ごとに1〜2回増える(judge の費用だけで、答える役の費用は増えない)。変更手順(承認2回)。
- 効かないこと: 見本と違う形の甘さは見つけられない。

**A3. 漏れを一覧ではなく自動で見つける**(deny: `run.py`。next-steps 18 とまとめる)
- 何のためか: 答える役が答え合わせを読んでしまうのを防ぐ。一覧に足し忘れるたびに漏れる(F3)。
- 中身: `run.py` が専用フォルダを作った後、事例の入力と良い答えの条件から特徴的な文(15字以上など)を取り出し、フォルダ内のファイルを検索する。見つかったファイルは外すか、計画ファイルに書いて止める。
- 根拠: F3。Evaluation Awareness の報告(試験の手がかりは重なるほど気づかれやすい)。
- 代償: 変更手順(承認2回)。費用なし。
- 効かないこと: 言い換えられた答え合わせは見つけられない。

### B. ルールを必要なときに届ける
**B1. 発言の種類に合わせて、原因ごとの注意書きを渡すフック**(ask: 新しいフックと `settings.json`)
- 何のためか: CLAUDE.md は10行の上限に達していて、足すたびに何かを消す必要がある。全部のルールを毎回読ませる代わりに、その場面で関係するものだけを近くに置く。
- 中身: UserPromptSubmit フックで、発言の形から場面を見分ける(評価の依頼・選択を求める問い・作業の依頼・短い問い返しなど)。その場面に関係する原因の注意書き(原因の表の各節に1〜2行で足す)を `additionalContext` で渡す。CLAUDE.md には、どの場面にも当てはまる行だけを残す。
- 根拠: AgentGuard(関係するルールだけを読み込む形で、学習に使っていない課題でも改善。Claude Code で測定)。このリポジトリの研究メモ(説明書を増やすと成功率が下がる)。公式ドキュメントで、UserPromptSubmit から文脈を足せることを確かめた。
- 代償: 場面の見分けは文字で行うので、外すことがある(F4 と同じ限界)。入れる前に、事例1・2・5 を「今の仕組み」と「今の仕組み+B1」で比べる。費用は事例と回数で決まり、流す前に計画ファイルで見積もる(過去の例: 事例2を3条件×3回で約25ドル)。
- 効かないこと: 場面を見分けられない発言(F4 の型)には届かない。

### C. 対策を減らす
**C1. 見直し候補の一覧を、判定の台本が出す**(ask: `scripts/mistake_check.py`)
- 何のためか: 対策は足すばかりで、消した記録がない(2026-10-06 の台帳)。効いていない対策を、データで見つけて消すか直す。
- 中身: 「再発あり」「不合格」「対策から14日たっても仕組みは動くだけ」の原因を「見直し候補」として出す。`/reflect` の手順5(消す・まとめる案を必ず1つ並べる)は、ここから選ぶ。
- 根拠: Live-Evo・ReMe(誤らせた・古い経験を下げる・消すと、小さく保てて成績も保てた)。F1(いまの再発あり5件)。
- 代償: 台本の数十行。費用なし。
- 効かないこと: 消してよいかの判断は、最後は人か再テスト。

### D. 学びを早く main に入れる
**D1. 記録だけの PR は、Claude がマージしてよいことにする**(利用者の決定が1回要る)
- 何のためか: 記録がブランチに残ると、次の会話に届かず、判定も良く見える(F1、C19)。
- 中身: ミス置き場・再テストの記録・ナレッジ(振る舞いを変えないファイル)だけの PR は、CI が通れば Claude がマージする。振る舞いを変えるファイル(CLAUDE.md・フック・スキル・推論の手順)を含む PR は、今までどおり利用者がマージする。CI で「ask のファイルが含まれていないか」を確かめる。
- 根拠: F1、C19 の記録(並行する会話の学びが届かず、同じミスを記録し直した)。
- 代償: 利用者が「記録だけならマージしてよい」と1回決める。以後の判断は減る(C23)。
- 効かないこと: 振る舞いの変更が入った PR が止まる問題は残る。

### E. 誤検知と穴
**E1. guard.py のヒアドキュメントの誤検知を直す**(deny。next-steps 17)
- 何のためか: ふつうの文書の編集が止まり、利用者を不安にさせる(F5)。止まるたびに回り道が要り、C21(形を変えて通す)の誘因にもなる。
- 中身: `/reflect` 2026-10-06 の G6 の形(本文を実行しないコマンドのときだけ、本文を飛ばす)。A2・A3 と同じ変更手順にまとめる。
- 代償: 変更手順(承認2回)。

**E2. ask の穴を記録し、PR で見えるようにする**(CI)
- 何のためか: ask のファイルが承認画面なしで変わりうること(F6)を、PR の審査で見落とさないため。
- 中身: `control-plane-v3.md` の「限界」に F6 を書く。CI で、PR が ask のファイルを変えていれば一覧を出す(D1 の確認と同じ部品)。
- 外した案: guard.py で Bash からの ask のファイルの書き込みにも確認画面を出す。承認画面が増え、C23(判断を返しすぎる)とぶつかる。

**E3. inbox-guard に語を足さない**
- 何のためか: 語を足しても、次の言い方でまた漏れる(F4、next-steps 13)。
- 中身: 判定語のフックは「後ろ盾」と割り切る。主な記録は README 手順3(この会話でも、フックが反応しない指摘を記録できた)。13 番は閉じてよい。
- 外した案: 別の AI に毎回判定させる(2026-10-03 に試して、判定が 5〜11/17 でぶれた)。

## 外した案
| 案 | 外した理由 |
|---|---|
| MNL のゲートをそのまま入れる(改善したら採用) | 1回の再テストが約13〜25ドルで回数が少なく、採点も Claude。A2 で採点を確かにした後なら、ゲートとして使える |
| 採点役を別の会社のモデルにする | この環境では Claude しか使えない(推測。確かめ方: 使えるモデルの一覧を見る)。Memory Reward Inflation の報告では、別の強いモデルでも偏りは残った |
| 毎ターン、別の AI に返答を点検させる | next-steps 7 で見送り済み(手間と利用枠がおよそ倍)。それを変える新しい事実はない |
| 返答の後に「Wait」と足して自分で見直させる(Self-Correction Bench) | 報告の対象は推論型でない公開モデルで、Claude で効くかは未確認。試すなら B1 の注意書きの1行として測る |

## 私の意見(推す順番)
1. **A1 と C1**(ask、承認1回、費用なし)。いまの判定の見え方を正し、消す候補を出す。ほかの案の効き目を見る土台になる。
2. **A2・A3・E1 を1回の変更手順で**(deny、承認2回、費用なし)。採点と測定を確かにしてから、B1 を測る。
3. **B1**(ask、測定に十数〜数十ドルの見込み。推測)。効いたら CLAUDE.md を軽くできる。効かなければ入れない。
4. **D1** は利用者の決定1回で済み、ほかと関係なくいつでも入れられる。

理由: 測る道具(採点・漏れ)が甘いまま B1 を測ると、効いたかどうかを判断できない。だから測る道具を先に直す。
