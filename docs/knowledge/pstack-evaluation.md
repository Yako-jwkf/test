# pstack-claude の評価と、そこから出た案の試験(2026-10-03)

要約: pstack-claude はプラグインとしては入れない(クラウドでは読み込まれない)。そこから出た3案を試した結果、「別の読み手」は採らない、「毎ターン判定フック」は今の仕組みと差がなく入れない、「目隠し」はパスの名前だけを run.py の次の直しのときに変える。どれも回数が少ないので、限界の欄と一緒に読む。

## pstack-claude とは
- Lauren Tan(README では「poteto」)が Cursor 向けに作ったスキル集 pstack を、michael-denyer が Claude Code・Codex・Pi などに移植したもの。2026-10-03 時点で v0.9.63、MIT ライセンス。
- 入口は `poteto-mode`。作業の種類(バグ・機能・リファクタ・計画など)に合う手順を選び、ほかのスキルを呼ぶ。スキルは54(うち考え方の資料 `principle-*` が23)。
- 入れると、SessionStart フックが会話のたびに「複数ファイル・設計・原因不明のバグなら poteto-mode を使え」という文を差し込む。

## 入れない理由
- クラウドのセッションは、リポジトリの設定に書いたプラグインを入れない。`/plugin` もクラウドでは使えない(公式ドキュメント)。スキルだけなら、claude.ai で有効にするか `.claude/skills/` に置けば読み込まれる。
- ローカルで使う場合も、`poteto-mode` の「可逆な作業や評価の開始は聞かずに進める」が、このリポジトリの「費用の見込みを見せて了承を得てから流す」と逆向き。ここの作業はほとんどが設計なので、ほぼ毎回 `poteto-mode` に回される。
- 中身の半分ほどはコード・PR 向け(このリポジトリにはアプリのコードがない)。

## 取り込みを考えて外した考え方
| pstack の考え方 | 外した理由 |
|---|---|
| 繰り返す指示は仕組みにする | `/reflect` の手順5に同じ考えがある |
| 直しても失敗が続くなら前提を疑う | next-steps 13 ですでに気づいている |
| 作業の記録を会話記録と照らす | 照らすのも同じ Claude なので、記録の作り話は防げない |
| 3つの別モデルに穴を探させる | 費用に見合わないとして見送り済み(next-steps 7) |
| わかりやすく言い直させる(`bro`) | CLAUDE.md の「専門用語に短い説明」とほぼ同じ |

- 目隠しの補足: 実務でも CLAUDE.md とサブエージェントの一覧に `/retest`・judge・「試される側」が出る。試験にだけある手がかりは、主にパス。パスは none・prev・mech に同じようにかかるので、ルールの効き目の差より、合格率の全体の高さに効くと推測する。
- 2025年の研究(arXiv 2505.14617)では、推論モデルが試されていると気づくと安全面の振る舞いが変わると報告(要約のみ)。対象は危険な依頼への応じ方で、ルールを守るかではない。

## 限界
- (c) は事例1件・各3回。直前の返答を発言に貼り付けた形で、本番の会話とは違う。気づきにくい指摘では差が出るかもしれない(未確認)。
- (d) の17件は、記録済みの指摘を短く切り出したもの。実際の会話の中に埋もれた形とは違う。
- 目隠しは事例1件・各5回。「大きな差はない」までしか言えない。小さな差の有無は分からない。
- 試験は `run.py` ではなく、その場で作った台本で流した(台本は残していない。測る道具を2系統にしないため)。違い: 事例3の原文が書かれた2ファイルを答える役のフォルダから外した、空のミス置き場を置いた。

## 副産物
- 事例1の条件1は 10/10。2026-10-02 にルールを直した後の再測定(未実施だった)の参考値。上の限界の試験の作りで測った値。
- `control-plane-v3.md` と `next-steps.md` に事例3の指摘の原文が書かれていて、`run.py` の `LEAK_FILES` に入っていない。事例3を `/retest` で流すと答える役が読める(next-steps 18)。
