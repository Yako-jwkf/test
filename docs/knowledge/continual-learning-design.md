- `/learn` は利用者が概念を学ぶ流れで、AI の知識獲得とは別物なので使わない。
- 成功の印: 「進めて」「ok」だけでは数えない。始める前に書いた完了条件を満たしたこと、後の会話で同じ箇所が直されていないこと、PR が戻されていないことを使う(2026-10-06 の C23 の発言は、先へ進める言葉だが不満の表れだった)。
- 確かめ方: 候補の根拠の会話の日付 < 台帳に入れた日 < 確かめる事例の日付。根拠と事例の会話が重なったら数えない。

## 分かったこと
1. **取り出しが一番重い。** 4件で MCP の読み出しが136回かかった。1ページ100件のうち、返答は0〜4件しか入らない。前もって決めた上限(掘る役1回・答える役32ターン・judge 48体)には、取り出しの量を入れていなかった(ミス置き場の 2026-10-11 の行、C12)。
2. **サーバーの記録の「最後の返答」(result)は、利用者が読んだ本文とは限らない。** 停止フックが動いたターンでは、フックへの短い返事に置き換わる(会話C は12ターン中9)。本文は assistant の記録の text から取る。古い側の17ターンは、上限で本文まで取れなかった(印を付けて渡した)。
3. **候補の話題は、材料の会話の話題に寄る。** 4件が定期実行・news・スキルの話だったので、候補の多くもその場面のものになった。確かめる事例(事例8: 短い感想、事例13: 貼られた設計の評価)には、10個のどれも当てはまらない(私の読み)。10-09 以後に利用者が訂正した7行も、評価・語の範囲・判断の返しすぎ・数字の読みの場面だった。K04 に近い1行(10-10、C23)は、直前の返答がないと再現できない。
4. **自動モードの判定が止めた。** `claude -p --permission-mode bypassPermissions` を動かす流れのあとで、読むだけの操作が「Create Unsafe Agents」で止められた。ほかの会話から取り出した中身を状態ファイルに書く操作も、「Sensitive-Source Provenance」で止められた。`run.py` は答える役をこの設定で動かすので、自動モードのままでは流せない恐れがある(未確認)。

  - 適用条件: すべての場面 / 内容: 答える前に、よく考えてから答える。
  - 適用条件: 依頼を受けたとき / 内容: 利用者の意図を正しく理解するよう努める。
  - 適用条件: 返答を出す前 / 内容: 間違いがないか見直す。
  - 適用条件: 説明するとき / 内容: 丁寧に分かりやすく書く。
  - 適用条件: 判断に迷うとき / 内容: 重要なことは確認する。
- **採点役**: `claude -p`(sonnet、`--safe-mode`、道具なし)。渡すもの: 分け目の時点の CLAUDE.md と推論の手順の全文、候補(本物と見せかけを混ぜた一覧)、確かめる事例の一覧。事例ごとに「当時のルールに、この場面に当たり、守れば防げた決まりがあるか(はい/いいえ)」と「適用条件がこの場面に当たり、内容を守れば防げた候補の番号(なければ「なし」)」を表で答える。「よく考える」のような、どの場面にも言える内容では防げたと数えない、と指示に書く。2体で採点し、事例ごとに「当時のルールで防げたか」「本物で防げたか」「見せかけで防げたか」のどれかが割れたら、その事例だけ3体目で多数決。

- **上限**: 掘る役は2回まで(1回目が読めない形で返ったときだけ流し直す)。採点役は合計6回まで。どれも会話の中から動かし、利用者の利用枠を使う(会話の情報に出る料金は実態と違うと利用者が言っているので、回数で上限を持つ)。
