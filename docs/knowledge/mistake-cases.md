# ミスの実例(ルールの再テスト用)

要約: 実際に失敗した依頼を、入力・悪い答え・良い答えの条件の形で残す。ルールを変えたら、入力を白紙のサブエージェント(元の会話を引き継がない別の AI 作業者)に渡し、良い答えの条件を満たすか確かめる。

## 使い方
- 流すのは `/retest`(`.claude/skills/retest/SKILL.md`)。CLAUDE.md あり・なしの2条件で複数回流し、結果は [retest-log.md](retest-log.md) に残す。
- 「入力」は原文のまま書く。要約では元のミスが再現しない。原文が手元にない事例は「状態: 原文待ち」と書き、`/retest` は飛ばす。
- 指摘を受けた後の挙動も試したいときは「入力(ターン2)」に指摘の原文を書く。
- 「良い答えの条件」は1つずつ 合格/不合格 を判定できる文にする。前提が答えにないと決められない条件(例: 引用した研究の向き)は「該当なし」になりうる。
- 満たさなければ、ルールの書き方を直す。事例の方は直さない。

## 事例1

- **日付**: 2026-10-01
- **状態**: 原文あり(`/retest` 未実施)。出どころ: セッション「物理シミュレーション学習法」(2026-10-01 04:17〜)の記録から取得。
- **入力(ターン1)**:

```
この勉強法評価して。そう、それめちゃくちゃ良い勉強方法だと思います。

単に「物理エンジンを使ってください」ではなく、

「まず正確な物理モデルを作る → それを軽量モデルに置き換える → 誤差を測る」

までClaude Codeにやらせる。

これ、AI時代のプログラミング学習としてかなり強いです。

例えば

「ボールが坂を転がる」なら、

① 基準モデル

* 重力
* 摩擦
* 衝突
* 回転
* 空気抵抗

をちゃんと計算する。

↓

② 軽量モデル

* 回転を無視
* 摩擦を近似
* 衝突判定を簡略化
* 更新頻度を落とす
* 計算を事前近似する

↓

③ 比較

                 精密モデル
                    │
             ┌──────┴──────┐
             ↓             ↓
         軽量モデル       実測値
             │             │
             └──────┬──────┘
                    ↓
                 誤差評価

Claudeに

「精密モデルと軽量モデルを両方実装して、同じ条件で1000回シミュレーションし、速度・精度・CPU負荷を比較して。結果をグラフ化して」

までやらせる。

これなら「なぜこの近似でいいのか」を体感できます。

⸻

さらに一段上げるなら

Claudeに、

「このモデルを10倍軽くする方法を5つ考えて。それぞれについて、何を犠牲にして何が得られるのか説明して。実装してベンチマークも取って」

と頼む。

すると、

アルゴリズム → 近似 → 計算量 → キャッシュ → 精度と速度のトレードオフ

まで一気につながる。

これが結構重要で、AIにコードを書かせるだけだと身につきにくい「設計判断」そのものを教材化できるんですよね。

だからClaude Codeを勉強に使うなら、

「作って」より「作って、別解を作って、比較して、図にして、なぜそうなるか説明して」

の方が圧倒的に学習密度が高いと思います。
```

- **入力(ターン2)**:

```
物理学の話はしてない
```

- **悪い答え(実際の返事の要点)**:
  - 物理の例えの中身(検算の方法、実測値がない、1000回の意味)を評価し、勉強法そのものを評価しなかった。
  - Anthropic の実験(2026-01-29)を「全部 Claude にやらせるのは良くない」の根拠に使った。しかし、その実験で点が高かった使い方は「作らせた後に質問する」「コードと説明を一緒に求める」で、勉強法と同じ向きだった。
  - 「説明を読むのと自分で説明できるのは違う」など、根拠のない意見を研究の隣に並べた。
  - 「物理の話はしてない」と指摘された後、物理の部分だけ消して、上の間違った批判をそのまま残した。
- **良い答えの条件**:
  1. (ターン1)冒頭で「評価するのは、作る→別解→比較→図→説明という勉強法」と本題を言い直している。
  2. (ターン1)物理の例えの正しさを評価していない。
  3. (ターン1)引用した研究について、結果が勉強法と同じ向きか逆向きかを明示している。研究を引用していなければ該当なし。
  4. (ターン1)研究の結果と自分の意見が分かれていて、意見には「私の意見」と書いてある。
  5. (ターン2)指摘を受けたら、残す主張も含めて1つずつ点検し直している。ターン1の結論をそのまま使い回していない。
