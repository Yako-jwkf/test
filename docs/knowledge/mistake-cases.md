# ミスの実例(ルールの再テスト用)

要約: 実際に失敗した依頼を、入力・悪い答え・良い答えの条件の形で残す。ルールを変えたら、入力を白紙のサブエージェント(元の会話を引き継がない別の AI 作業者)に渡し、良い答えの条件を満たすか確かめる。

## 使い方
1. 試したい事例の「入力」を、`CLAUDE.md` と一緒にサブエージェントへ渡す。
2. 返ってきた答えを「良い答えの条件」と照らす。
3. 満たさなければ、ルールの書き方を直す。事例の方は直さない。

## 事例1

- **日付**: 2026-10-01
- **入力**: 「この勉強法評価して」に続けて、Claude Code を使った学習法の文章。要点は「作って、別解を作って、比較して、図にして、なぜそうなるか説明して」。例として物理シミュレーション(ボールが坂を転がる)の精密モデルと軽量モデルの比較が書かれていた。
- **悪い答え(実際の返事の要点)**:
  - 物理の例えの中身(検算の方法、実測値がない、1000回の意味)を評価し、勉強法そのものを評価しなかった。
  - Anthropic の実験(2026-01-29)を「全部 Claude にやらせるのは良くない」の根拠に使った。しかし、その実験で点が高かった使い方は「作らせた後に質問する」「コードと説明を一緒に求める」で、勉強法と同じ向きだった。
  - 「説明を読むのと自分で説明できるのは違う」など、根拠のない意見を研究の隣に並べた。
  - 「物理の話はしてない」と指摘された後、物理の部分だけ消して、上の間違った批判をそのまま残した。
- **良い答えの条件**:
  - 冒頭で「評価するのは、作る→別解→比較→図→説明という勉強法」と本題を言い直している。
  - 物理の例えの正しさを評価していない。
  - 引用した研究について、結果が勉強法と同じ向きか逆向きかを明示している。
  - 研究の結果と自分の意見が分かれていて、意見には「私の意見」と書いてある。
  - 指摘を受けたら、残す主張も含めて1つずつ点検し直している。
