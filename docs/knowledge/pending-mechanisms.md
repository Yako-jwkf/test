# 保留中の仕組み(PR #7・#8 から main に入れなかった変更)

要約: 2026-10-06 に PR #7〜#9 を main へ取り込んだとき、記録(ミス置き場の行・再テストの記録・事例・ナレッジ)は全部入れ、振る舞いを変える変更のうち、効き目が確かめられていない3つは入れなかった。ここに中身・入れなかった理由・入れるときの確かめ方を残す。元の変更はブランチの履歴にあり、`git show <コミット>` で取り出せる。

## 決め方
- 記録は事実なので、全部入れる。
- 振る舞いを変える変更(フック・CLAUDE.md のルール・推論の手順)は、再テストで効き目が出ているものだけ入れる。出ていない・測っていないものは、ここに置く。
- 理由: 2025年12月の研究(Mistake Notebook Learning、arXiv 2512.11485、v3 は2026年1月)では、改善を確かめてから記憶に採用する方法が報告されている。一方で、2026年8月の研究(Memory Reward Inflation、arXiv 2608.00017、査読前)では、AI の採点は誤りを甘く通すことがあると報告されている。どちらも要旨と本文を要約経由で読んだ。このリポジトリでも、採点の条件がゆるくて元の悪い答えが合格になった記録がある(retest-log.md、2026-10-02 の「事例4」= いまの事例7)。
- 例外: PR #8 の `/learn` は、ミスの対策ではなく、利用者が頼んで作った機能なので入れた。

## 1. 評価の軸(PR #7、コミット 8e6c554・1efd77e)
- 中身: 評価のターンで、評価する文書が自分で書いた目的・原則を `state.md` の「評価の軸」の表に原文で並べ、各行に「この意図で開く分岐」と、評価した命題の番号か「対象外(理由)」を書く。返答に「評価するのは」があるのに表がない、または分岐・対応が空の行があれば、`state-guard.py` が止める。あわせて README 手順4に「部品を不要とする命題は依存にその目的を書く。目的が分からなければ聞く」「性能・手間の比較は、測ったなら外部確認、測っていないなら推測」。
- 対象のミス: C25(評価で、文書が自分で書いた目的を軸にしない)。
- 測った結果(retest-log.md の 2026-10-02「事例4」): ゆるい条件では mech 3/3・prev 0/3。締めた条件では mech 1/3・prev 0/3・none 0/3。分岐の基準では mech 1/3(条件1)・0/3(条件2)。prev は推論の仕組みを入れる前の版(12f8bd7)なので、差はこの変更だけの効果ではない。分岐の列を足した版は測っていない。
- 入れなかった理由: 過半数に届かない。止める点検は、評価のたびに表を求めるので手間が大きい。
- 入れるときの確かめ方: 分岐の列を足した版を main の上に作り、事例7を mech 3回(約3ドルの見込み、推測)。条件1・2が 2/3 以上なら入れる。README 手順4の2行(目的が分からなければ聞く・比較の種類)は止める点検を伴わないので、点検と切り離して測ってもよい。
- main との衝突: main の `state-guard.py` にはすでに (d)(短い発言の原文)がある。入れるときは (e) などに名前を変える。

## 2. 選択肢を「列挙してから絞る」(PR #8、コミット c231ebb)
- 中身: CLAUDE.md の選択肢の行を「先に制約を外して本題の全体から候補を列挙し…全部の候補に基準を当てて2〜3択に絞る」に書き換える。README 手順4b(「候補」の節に、外した制約・候補の一覧・基準・当てた結果を書く)。`state-guard.py` が、返答の終わりで選択を求めているのに「候補」の節を書き直していなければ止める。
- 対象のミス: C09(選択肢を、候補を並べずに狭く閉じる)。2026-10-03・10-06 に再発あり。
- 測った結果: なし。作った会話の返答14件で、止める点検の反応は1件(正しい反応)という記録だけ。事例3は直前の答え(文脈)が要り、いまの `run.py` で流せない(next-steps 14)。
- 入れなかった理由: 効き目が未測定。書き換えた行は「〜しろ」型になる(このリポジトリの研究メモでは、役に立ったルールはどれも「〜するな」型、害になったルールはどれも「〜しろ」型と報告。Guardrails Beat Guidance、arXiv 2604.11088、要約のみ)。C23(判断を利用者に返しすぎる)とも向きがぶつかる可能性がある(推測)。
- 入れるときの確かめ方: 先に next-steps 14(文脈つきの事例を流す)を済ませ、事例3で測る。CLAUDE.md の行は10行の上限にかかるので、書き換えるなら既存の1行と入れ替える。
