# ボスAIの設計方針

要約: ボスAIは「情報を取る → 判断する → 行動する」の3段に関数を分ける。小規模なら判断はif文(回避を先頭)、プレイヤー100万人・ボス100万体・技100万個なら、情報はマス目の名簿、判断は技の表と点数に中身だけ差し替える(2026-10-06 の会話で決めたこと)。

## 経緯
- 別の AI が書いた「ボスAIにビヘイビアツリーや当たり判定(Collision)のセンサーは要らない。判断のときにプレイヤーの情報を直接取ればよい」というまとめを評価し、そこから設計を決めた。
- 「個人制作」という前提は、まとめの最後の段落からの推測。ユーザーには未確認。

## 元のまとめの評価で見つかった穴
- 中心の考え(AIに要る情報と、その取り方を分ける)は正しい。判断が各 Collision に散らばる問題の原因を外している。
- 4節の見出し「レイでいい」に対し、本文にレイが出てこない。レイは当たり判定の仕組みを使う問い合わせなので、「Collision を使わない」は言い過ぎ。分けるべき線は「Collision に判断を持たせて結果を流し込む」か「判断のときに問い合わせる」か。
- 取得する情報の一覧に「プレイヤーが見えているか(遮蔽物)」がない。
- if文の例で回避が3番目にあり、近くで攻撃されても近接攻撃が選ばれる。条件の管理の問題は Collision をやめても消えず、if文の並び順に移る。
- 判断のきっかけが「しばらく待つ」だけで、反射的な回避が遅れ、自分の攻撃を途中で切る。
- Collision を外したことは、ビヘイビアツリーが要らない理由にならない(判断の組み方と情報の取り方は段が違う)。
- 「常時の Collision は処理が増える」は、ボス1体・プレイヤー1人なら理由として弱い。ボス100万体なら逆に一番の問題になる。

## 決めたこと: 3段に分ける
- 情報を取る関数: 距離、角度、プレイヤーが攻撃中か、見えているか(レイ1本)を返す。
- 判断する関数: 行動を選ぶ。呼ぶのは、今の行動が終わったときと、割り込み(被弾した・相手が攻撃を始めた)のときだけ。
- 行動する関数: 選ばれた技を実行する。
- 規模が変わっても、差し替えるのは「情報を取る」と「判断する」の中身だけ。

## 小規模(ボス1体・プレイヤー1人・技が数個)
- 判断は if文。回避を先頭に置く。
- 外したもの: 最初から表と点数(if文より長く、食い違いもまだない)、ビヘイビアツリー(技を枝にすると並び順の管理が残る)、常時のトリガーのセンサー(判断が散らばる)。
- 切り替える合図: if文の並び順で行動が食い違い始めた → 判断を表と点数に。処理が1フレームに収まらない → 情報の取り方と判断の回数を変える。

## 100万規模(プレイヤー100万人・ボス100万体・技100万個)
置いた前提(例の数値): 1つの広い世界、ボスはサーバーで動かす、見る範囲は半径50m、サーバーの更新は1秒に20回。

- 情報の取り方: 世界を一辺50mのマス目に分け、マスごとにプレイヤーの名簿を持つ。名簿の書き換えはマスをまたいだときだけ。ボスは自分と周り8マスの計9マスだけを見る(半径50mならこの9マスで覆える)。9マスに誰もいないボスは眠らせ、プレイヤーがマスに入ったら起こす。
- 狙う相手: 9マスの候補のうち、このボスへのダメージ合計が一番大きいプレイヤー。
- 技の表: 番号・種類・届く距離・再使用までの待ち時間・相手が見えている必要・基本の点。ボスごとに持ち技を最大16個。相手が攻撃中なら回避の点を3倍にする(回避の優先が並び順でなく数で決まる)。1体が100万個すべてを使うなら、届く距離の段ごとに基本の点の高い順の一覧を前もって作り、上から数個だけ見る。
- 判断の回数: 起きているボスを4組に分け、1回の更新で1組ずつ判断(各ボスは0.2秒に1回)。割り込みがあったボスは順番を待たずにその回で判断する。
- サーバーの見積もり: 起きているボス100万体が1秒5回判断すると毎秒500万回。1回10マイクロ秒と仮定すると50コア分(10マイクロ秒は根拠のない置いた数。作って測る)。世界を区域に分けて1区域1台。境目から50m以内のプレイヤーの位置は隣のサーバーから写しを受け取る。
- 技の作り方: 1個1分で手作りすると100万分(休みなしで約1.9年)。部品の組み合わせ(例: 動作100 × 属性10 × 範囲10 × 強さ100)で表をプログラムで作り、表の点検(距離がマイナスでない、強さが上限以下など)も自動にする。

```
判断する(ボス):
  候補 = 周り9マスの名簿
  候補が空 → 眠らせて終わり
  相手 = 候補のうち、このボスへのダメージ合計が一番大きいプレイヤー
  距離・角度 = 相手との位置の差から計算
  見える = ボスから相手へレイを1本
  持ち技を1つずつ: 距離が範囲外 / 待ち時間中 / 見える必要ありで見えない → 飛ばす
    点 = 基本の点(相手が攻撃中で回避の技なら ×3)。一番高い技を選ぶ
  一番 があれば実行、なければ相手に近づく
```

## 未確認のこと
- レイが当たり判定の仕組みを使う問い合わせであること(Unity の Physics.Raycast、Unreal の LineTrace)、Unity・Unreal・Godot のトリガーが「入った・出た」の通知が基本であること、Unreal にビヘイビアツリーが標準で入っていること。どれも記憶で、公式文書は開いていない。
- 使うゲームエンジンと、実際の規模(個人制作か)。
