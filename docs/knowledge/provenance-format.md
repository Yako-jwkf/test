# 出どころの共通形式(案)

要約: 主張・概念・要件の項目を、「誰が言ったか・どう確かめたか」の状態と出どころつきで書く共通の形。学習(`/learn`)、推論の状態ファイル(`.claude/reasoning/`)、要件定義 Agent(`prompts/requirement-agent-v1.4.md`)のあいだで、同じ意味の状態を読み替えられるようにする。2026-10-03 作成。**状態: 案**(状態の名前と、3か所で共通に使うかは、ユーザー未確認)。

## なぜ作るか
- 2026-10-03 の評価で、学習システムの資料4本のあいだで同じ言葉の意味がずれていた。Requirement v0.3 では、ほぼ同じ文が場所によって user_confirmed と agent_interpreted に分かれていた。
- 推論の状態ファイル・学習・要件定義 Agent は、どれも「まとまり・つながり・状態・出どころ」を持つ(2026-10-03 の会話での私の意見)。状態の意味を揃えておけば、ある場所で作ったもの(撤回の連鎖など)を別の場所でも使える。

## 1項目の書き方

| id | 内容 | 状態 | 出どころ | 日付 |
|---|---|---|---|---|

- **出どころ**: 本人の発言なら原文の引用。資料ならタイトル・ページや URL と「本文/要約のみ」。AI の解釈なら、何から出したか。
- 同じ項目は1か所にだけ書き、ほかの場所では id で指す。要約の節に内容を書き写さない(v0.3 では書き写した文が場所ごとにずれた)。

## 状態

| 状態 | 意味 | 要件定義 Agent v1.4 | 推論の状態ファイル | 学習(`/learn`) |
|---|---|---|---|---|
| 本人 | ユーザーが自分で言った | user_stated | (指摘の欄の原文) | あなたが入力した概念、あなたが言った関係 |
| 本人確認 | AI が出したものを、ユーザーが確認した | user_confirmed | 外部確認(ユーザーへの確認) | 地図や学ぶ順を、あなたが「これでいい」と言ったもの |
| 確かめた | 文章の外から返ってきた結果 | — | 外部確認 | Recall であなたが実際に答えた結果 |
| 資料 | 本・論文・Web・ドキュメントに書いてある | research_informed | 報告 | 教科書などの記述 |
| AI の解釈 | AI が出した。確かめていない | agent_interpreted | 導出・推測・私の意見 | AI が出した概念・関係・学ぶ順の案 |
| 仮定 | 作業のために置いた前提 | assumption | 仮定 | — |
| 委任 | ユーザーが判断を任せた。任せた先と範囲も書く | delegated | — | Story / Rhyme(v0.3 の D1) |
| 不明 | 分からない、決まっていない | unknown | — | v0.3 の U1〜U5 |

## 決まり
- 状態を上げるとき(AI の解釈 → 本人確認 など)は、上げた根拠(確認した発言の引用、Recall の答え)を出どころに足す。
- 「確かめた」と書いてよいのは、状態が「確かめた」と「本人確認」の項目だけ。「資料」は確かめたことにならない(推論の状態ファイルの「報告」と同じ扱い)。
- 各場所の細かい種類(推論の状態ファイルの導出・推測・私の意見など)は、その場所ではそのまま使ってよい。この表は、別の場所へ渡すときの読み替えに使う。
