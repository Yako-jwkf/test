# ミスの原因の表

要約: ミス置き場(出来事)の行を原因ごとに束ね、原因ごとに「推測した原因・置いた対策・擬似解消関数(解消したかを仮に判定する方法)」を持つ。解消したかは `python3 scripts/mistake_check.py` で判定する。対策を置いたこと(置き場の「対策」の列)と、ミスが直ったこと(この表の判定)は別に扱う。

## 書き方
- 原因ごとに `### Cnn 名前` の節を1つ作る。置き場の行の「原因」の列に、この番号を書く。
- 各節は次の項目を、`- 項目: 内容` の形で書く。
  - 原因の推測: なぜ起きたか。種類(推測/確かめた)を先頭に書く。
  - 対策: 置いた対策と場所。まだなければ「なし」、見送ったら「見送り(理由)」。
  - 対策日: 対策を置いた日(YYYY-MM-DD)。この日より**後**の出来事を再発と数える。同じ日の出来事は数えない(日付しか持たないため)。
  - 擬似解消関数: 判定の方法。`、` で区切って複数書ける。
    - `振る舞い:名前` — 記録した入力でフックなどが期待どおり動くかを、台本(`scripts/mistake_check.py` の同じ名前の関数)で試す。
    - `再テスト:事例N-条件M>=k/n` — `/retest` の結果で判定する。結果は下の「最後の再テスト」に書く(台本は `/retest` を流さない。費用がかかるため)。
    - `残存:ファイル:文字列` — 対策の文がまだ残っているか。効き目ではないので、これだけで合格しても「残存のみ」と表示する。
    - `なし(理由)` — 文字では判定できない。再発の数だけで見る。
  - 最後の再テスト: `事例N-条件M=k/n(YYYY-MM-DD)` を `、` で区切って書く。
- 原因の分け方は私の読み(推測)。分け方を変えたら、置き場の「原因」の列も直す。

## 解消の状態の決め方(台本の判定)
上から順に当てはまったものにする。

| 状態 | 条件 |
|---|---|
| 見送り | 対策が「見送り」 |
| 未対策 | 対策日がない |
| 再発あり | 対策日より後に、同じ原因の出来事がある |
| 不合格 | 擬似解消関数のどれかが不合格 |
| 合格(暫定) | 振る舞いか再テストで合格し、不合格がない |
| 合格(残存のみ) | 合格したのが残存の確認だけ |
| 未判定 | 判定できる関数がない(再発がないだけ) |

「合格」でも暫定。擬似解消関数は、記録した入力や事例で試すだけで、新しい場面で起きないことまでは確かめない。
